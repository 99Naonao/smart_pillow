## 一、协议框架
### 协议格式

| 说明  | 起始字段 | 长度          | 功能号 | 数据  | 协议校验CRC16 |
| --- | ---- | ----------- | --- | --- | --------- |
| 长度  | 1    | 2           | 1   | n   | 2         |
| 下发  | 55   | 低字节在前，高字节在后 |     |     | 低在前，高在后   |
| 上传  | AA   |             |     |     |           |
**说明：**
协议校验: 功能号 + 数据 进行MODBUSCRC16校验
长度：功能号 +  数据内容
应答：功能号的bit7=1作为当前命令的应答位
通讯方式：半双工功能，使用主从模式，蓝牙作为主机，枕头作为从机，主机向从机请求数据，从机应答
所在类型的内存：采用小端模式，即低字节在前，高字节在后
特别说明：
命令有分写和读功能，区分：功能号的最高位bit7为1时，该命令是读功能，这时，下发命令中数据区是没有，长度一直为1，枕头返回的是该命令的字段信息

### 写命令应答

|     | 长度和类型  | 数据  | 备注                     |
| --- | ------ | --- | ---------------------- |
| 功能号 | unit 8 |     | 与写命令功能一样               |
| 应答码 | unit 8 |     | 0x00：执行成功<br>0x01：执行失败 |

### 心率模块控制读取 0x0F

|             | 长度和类型    | 数据   | 备注                                        |
| ----------- | -------- | ---- | ----------------------------------------- |
| 功能号RW       | unit8    | 0x0f | 心率模块控制读取                                  |
| 写/读标志       | unit8    |      | 0: 代表将data0~datan写入到心率模块当中<br>1：读取心率模块的数据 |
| data0~datan | unit8[n] |      |                                           |
注意：data0~datan就是通讯协议的内容，上位机软件要去解析通讯协议内容
发送完上位机命令后，隔200ms后再去读取心率模块

- 上位机下发指令

| 固定    | 配置wifi | 备用  | 获取状态  | 备用  | 备用  | 备用  | CHK（1byte） |
| ----- | ------ | --- | ----- | --- | --- | --- | ---------- |
| 5A 5A | 0A/00  | 0A  | 0A/00 |     |     |     |            |
指令说明:
1)配置设备WIFI:配置WIFI账号发0A,不用此位发00
2)获取设备联网状态:获取状态发0A,不用此位发00
3)CHK:所有位数的异或值
举例:
1)开始配置WIFI发送:5A 5A 0A 00 00 00 00 00 CH
2)下位机收到此指令后会把此指令发回给上位机以示接收成功。
- 下位机上发指令

| 固定    | 配置wifi | 备用  | 获取状态  | 备用  | 备用  | 备用  | CHK（1byte） |
| ----- | ------ | --- | ----- | --- | --- | --- | ---------- |
| 5B 5B | 0A/00  | 00  | 0A/05 |     |     |     |            |
指令说明:
1) WIFI联网状态：0A已连接上网络，05未连接上网络
